## 1. Vocabulary

- **Storefront** — a place where the user owns games: Steam today, Xbox and PlayStation later. [code]
- **Steam connection** — the link between a SavePoint account and a Steam account, made by signing in with Steam on the account settings page. SavePoint can then read which games that Steam account owns. [code]
- **Sync (import)** — the action of pulling the user's owned games from a connected storefront into SavePoint. It can be repeated: each sync refreshes playtime and adds newly bought games. [code] [web]
- **Imported game** — one owned storefront game shown on the "Import from Steam" page, with its name, Steam icon, time played and last played. It is *not* in the user's library yet; the user decides what to do with it. [code]
- **Game catalogue** — SavePoint's shared record of games (title, cover art, release date, genres, time to beat), sourced from the external game database IGDB. One catalogue entry serves every user who has that game. [code]
- **Matching** — finding which catalogue game an imported game is. A Steam game is matched exactly by its Steam store identity, not by guessing from its title. [code] [web]
- **Needs a manual match** — an imported game the catalogue has no exact entry for; the user picks the right game by searching. [code]
- **Library** — the games the user tracks, each with a status: Want, Playing, or Done. Adding an imported game puts it in the library with a status the user chooses. [code]
- **Removed (dismissed) game** — an imported game the user chose to hide from the import list; a later sync does not bring it back. [code]
- **Sync job** — (new) one run of a sync for one user and one storefront, which has a visible state (waiting, in progress, finished, failed) and progress. [user]

## 2. What it does today

**Why this work [user]:** filling the library from Steam is slow — the user waits on the import, then matches and adds games one by one.


Today a sync is done while the user waits. [code]

1. The user connects Steam on the account settings page. The card then says "Steam Account Connected" and links to "Import from Steam". [code]
2. On the "Import from Steam" page the user presses **Import from Steam**. The button changes to "Importing…" and a toast says "Steam import started — This may take a few minutes. We'll notify you when it's complete." [code]
3. SavePoint asks Steam for the whole owned-games list in one go and saves it. A toast then says "Steam import completed — N game(s) imported successfully." [code]
4. The list shows each game with its Steam icon, time played, last played, and a suggested status. None of them is matched to the game catalogue yet, so no covers or release info are shown, and a warning says "Some games need a manual match". [code]
5. Matching happens only when the user adds one game: the add dialog tries to find the game in the catalogue; if it cannot, the user searches and picks it by hand. [code]

The feature being specified moves step 3–5's slow part into the background: after pressing Sync, the user can leave; SavePoint fetches the library and matches every game against the catalogue, showing progress, and the list then shows matched games with their catalogue info, while games without an exact match are flagged for a manual match. [user]

## 3. What it depends on

- A connected Steam account whose Steam privacy settings allow other people to see game details — "Game details" set to Public and "Always keep my total playtime private" unchecked. By default Steam sets game details to Friends only. [web] [code]
- Steam being reachable; Steam may refuse when asked too often. [code]
- The external game database (IGDB), which only answers a limited number of questions per second for all SavePoint users together — this is why a big library takes time and why the work happens in the background. [user] [web]
- A background service outside the main app that does the work after the user presses Sync. [user]

## 4. What it changes

- The "Import from Steam" list: new games appear, playtime and last played refresh, and games gain catalogue info (cover, title, release date) once matched. [code] [user]
- The game catalogue grows with games SavePoint has not seen before; every user benefits. [user]
- A visible sync status for the user: in progress with counts, finished with a summary, or failed with a reason. [user]
- ~~It does **not** add anything to the user's library on its own; the user still decides per game. [code] (assumed — open question 1)~~ *Superseded 2026-11-13:*
- Some users want their whole Steam library in SavePoint without curating game by game, so a sync can also add the matched games to the library. [user] The user opts in each time they start a sync ("add all games to my library", off by default); added games get the suggested status — Playing if played in the last 7 days, otherwise Want. [user]
- When a sync ends, the app tells the user. [user] SavePoint has no notification feature today, so this is new. [code]

## 5. Quirks

- **Normally:** "matched" means the game was found in the catalogue. **Here:** today the "matched" state means "the user added it to their library"; a found-but-not-added game leaves no trace. *Why it matters:* the new background match needs its own notion of "found", separate from "added". [code]
- **Normally:** a toast that says "we'll notify you" is followed by a notification. **Here:** the sync runs while the user waits and no notification exists. *Why it matters:* this spec makes that promise true, or the copy must change. [code]
- **Normally:** "N games imported" counts new games. **Here:** it counts every game touched, so re-syncing an unchanged library reports the whole library again. *Why it matters:* the new summary should count new games. [code]
- **Normally:** a private Steam library produces a clear error. **Here:** Steam can return an empty answer for a private library, which looks the same as owning no games, so the user may see "0 games imported successfully". [web] [code] *Why it matters:* an empty result needs a privacy hint, not a success message.
- **Normally:** a game you stop owning disappears. **Here:** games that leave the Steam library stay in the list; comparable apps also never auto-remove. [code] [web]
- **Normally:** the "needs a manual match" warning shows when some games need it. **Here:** it shows almost always, because every game is unmatched until added, and it tells the user to click a "Search" button that does not exist on the row. [code] *Why it matters:* after background matching, the warning can show only for games that really need it.
- **Normally:** pressing Sync twice starts one sync. **Here:** nothing prevents a second press except the button being disabled while the page waits; leaving and coming back would allow another start. [code] [web]
- **Normally:** a removed game can be restored to the list. **Here:** "Restore" opens the add dialog instead. [code] (left as is — out of scope)

## 6. Open questions

1. ~~Does a sync add games to the library automatically?~~ **Resolved [user]:** yes, the sync can add matched games to the library (details in 10).
2. Where can the user see sync progress? — *Assume:* on the "Import from Steam" page and on the Steam card in account settings; nowhere else.
3. ~~How is the user told a sync finished?~~ **Resolved [user]:** the app notifies the user when the sync ends. Open detail in 11.
4. ~~Can the user cancel a running sync?~~ **Resolved [user]:** no.
5. ~~Sync limit?~~ **Resolved [user]:** one sync at a time per storefront; no daily cap.
6. What does the finish summary count? — *Assume:* new games, games already on the list (refreshed), and games that need a manual match.
7. ~~What if part of the matching fails?~~ **Resolved [user]:** an explicit "finished with gaps / retry" behaviour is out of scope. *Assume:* games that could not be checked show as needing a manual match, like games with no catalogue entry.
8. ~~Is the "last synced" time shown?~~ **Resolved [user]:** out of scope.
9. ~~"What's new" correction?~~ **Resolved [user]:** in scope, together with the other misleading import copy (the "we'll notify you" toast, the "Click Search" hint, "0 games imported" for a private library).
10. ~~Adding to the library~~ **Resolved [user]:** choice per sync, off by default; suggested status (Playing if played in the last 7 days, else Want). Accepted consequence: a big, recently played library can put more than three games in Playing at once, bypassing the gentle "three in progress" nudge. Games already in the library are left as they are.
11. How does the end-of-sync notice reach a user who left the app? — *Assume:* a toast if they are in the app when it ends; otherwise a one-time notice the next time they open the app.
