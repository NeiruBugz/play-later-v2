## 1. Vocabulary

- **Game** — a title from the public game catalog (cover, description, platforms). Exists independently of any user. [code]
- **Library entry** — one person's relationship to one game. A game appears in someone's library at most once. It carries a status, an optional rating (1–10, shown as stars), platform, and start/finish dates. [code]
- **Status** — the single label on a library entry saying where the person is with the game. Today there are five: **Wishlist** (want it, don't own it), **Shelf** (own it, haven't started), **Up Next** (queued to play soon), **Playing**, **Played** (started and then finished *or* set aside). [code]
- **Replay** — not a status of its own: an Up Next game that was already played before is labelled "Replay" instead of "Up Next". [code]
- **Playthrough (run)** — one attempt at playing a game, belonging to a library entry. A game can have several. Each run has its own state (**Playing / Finished / Abandoned**), type (first playthrough or replay), dates, hours, platform, rating, and notes. [code]
- **Run-derived status** — when a game has runs, its status is normally calculated from them: any run in progress → Playing; otherwise → Played. [code]
- **Manual override** — a switch on the game page ("Set manually") that pins a status so runs stop changing it; "Follow my playthroughs" un-pins it. [code]
- **Journal entry** — a free-text note about a game, optionally with minutes played and optionally attached to one run. Each entry is labelled either **Quick note** or **Reflection**. The data can also hold a mood, tags, a title and a visibility setting, but none of these can be set anywhere in the app today. [code]
- **Session log** — the "Log" action (center button on mobile, pinned button on desktop): pick a game, optionally a run, enter hours, optionally write "What stayed with you tonight?". It creates a journal entry. [code]
- **Up Next queue (target)** — in the new model, an ordered short list of games you intend to play next. Today "Up Next" is just a status with no order. [code] [user]
- **Want / Playing / Done (target)** — the new three-status model from product definition v3.0: Want = not started (owned or not), Playing, Done = finished *or* let go. [user]

## 2. What it does today

**Adding a game.** There are seven ways in, and they disagree [code]:
- The search page and the "Start tracking" card on a game page add with one tap, as **Shelf**.
- The command palette (⌘K) adds with one tap, but as **Up Next**, with an undo.
- The library "+" opens a dialog where you type, press Enter, then tap "+". It adds as **Shelf**, and the dialog stays open afterwards.
- The game page status button lets you pick any of the five statuses (two taps).
- Steam import uses a five-option picker pre-filled with a suggested status.
- There is a global "Add game" action, but no button anywhere opens it.

**Changing status.** It takes 2–3 taps, and the result depends on where you do it [code]:
- **Game page.** Tap the status pill, then pick from a popover (desktop) or a sheet (mobile). If the game has runs, the pill is read-only, says "Follows your playthroughs", and has a near-invisible "Set manually" control to pin it.
- **Mobile game page.** The sticky bottom bar's status pill only scrolls you up to the hero.
- **Library card.** ⋮ → Change Status → pick.
- **List view only.** Cards show a one-tap next-step button: Shelf → "Queue It", Up Next → "Start Playing", Played → "Replay", Wishlist → "Add to Shelf", Playing → "Log Session". The default grid view has no such button.
- **"Edit details" form.** Setting a finish date silently switches the status to Played.

**Playthroughs.** The game page has a Playthroughs panel with a timeline. You can add, edit and delete runs through a form with nine fields. A new run defaults to "Finished", so adding one with defaults flips the game to Played. [code]

**Journal.** You can write notes from the compose dialog, the journal page, or the Log sheet:
- The Log sheet lets you choose a run when a game has several, and asks "What stayed with you tonight?". [code]
- Every new entry is saved as a "Quick note", so the "Reflection" label only appears on older entries. [code]
- Mood and visibility exist in the data but are invisible. [code]

**Up Next.** The dashboard shows up to 4 Up Next games, ordered by whichever was edited most recently. Editing any game reorders the "queue". [code]

## 4. What it changes

The status appears, or is used, on almost every screen:
- library filters and the status chips at the top of the library;
- the sidebar status list;
- the dashboard (status strip, stats bar, "Up next" rail, "Continue playing" hero);
- library cards (badge, colors, next-step button, "Tried" chip);
- the game page (status pill, mobile bottom bar, Playthroughs panel);
- the "Edit details" form;
- Steam import (picker, card badge);
- search results (an "in your library" badge);
- the profile ("played" and "completed" counts, "Recently played", Playthroughs section);
- friends' activity lines ("@x added Game to {Status}"). [code]

**Who sees it.** The owner sees everything. Friends see the status in activity lines and on the public profile. [code]

**Existing data.** Libraries already hold games in all five statuses, games with several runs, finished and abandoned runs, per-run ratings, and journal entries labelled Quick note or Reflection. All of it must land somewhere sensible. [code]

## 5. Quirks

1. **A status set from the library doesn't stick.** [code]
   - **Normally:** a status you set stays put.
   - **Here:** a status set from a library card, its menu, or the "Edit details" form gets silently overwritten the next time you add, edit or delete a playthrough. Only "Set manually" on the game page pins it.
   - **Why it matters:** this is a big reason the app feels unpredictable. The new model must make one tap the final word.
2. **The mobile bottom bar can disagree with the page.** [code]
   - **Normally:** a game marked Playing says "Playing" everywhere.
   - **Here:** a Playing or Played game with no runs shows "Shelf" in the mobile bottom bar while the top of the page says "Playing".
3. **"Played" doesn't mean finished.** [code]
   - **Normally:** Played = beat it.
   - **Here:** Played includes games you dropped. Separately, the profile counts "completed" by finish date.
   - **Why it matters:** Done = finished *or* let go formalizes what Played already is.
4. **Older dropped games look finished.** [code]
   - **Normally:** a dropped game stays recorded as dropped.
   - **Here:** when runs were introduced, every Played game got a run marked "Finished", including ones that were really dropped.
   - **Why it matters:** any finished-vs-let-go distinction cannot be trusted for older games.
5. **The default status depends on how you add.** [code]
   - **Normally:** adding a game puts it in the same place every time.
   - **Here:** ⌘K adds as Up Next, everything else as Shelf, and the game page asks you to pick.
6. **Up Next has no order.** [code]
   - **Normally:** a queue keeps the order you set.
   - **Here:** Up Next is sorted by last edit, so touching any game reorders it.
7. **"Replay" depends on which screen you're on.** [code]
   - **Normally:** a game has one label.
   - **Here:** the same queued game can read "Replay" on its library card and "Up Next" on its game page.
8. **Logging hours alone fails for some games.** [code]
   - **Normally:** "playtime alone is a complete log", as the screen says.
   - **Here:** for a game with no playthrough, saving hours without text is rejected. The compose dialog also keeps Save disabled until you type, despite saying thoughts are optional.
9. **There are two ratings.** [code]
   - **Normally:** one rating per game.
   - **Here:** there is a game-level rating (shown on cards, used by the filter, editable only via "Edit details") and a per-run rating (shown as "Best rating" and on the profile).
10. **Wishlist is the only way to say "I don't own it".** [code]
    - **Normally:** ownership is a separate fact from intent.
    - **Here:** ownership exists only as the difference between Wishlist and Shelf.
    - **Why it matters:** merging both into Want erases "not owned" unless it is kept another way. Product principle "pause before buying" needs it.
11. **The add dialog stays open after adding.** [code]
    - **Normally:** it closes, or confirms and stays open for adding more.
    - **Here:** it silently stays open.

## 6. Open questions

_All eleven assumptions below were accepted by the user on 2026-10-29 [user]; they are now the working decisions._

1. **Keeping "not owned" after Wishlist and Shelf merge into Want.** Assumption: Want carries a simple owned / not owned marker. "Wishlist" becomes a filter of Want, not a status.
2. **Done sub-type.** Assumption: Done has an optional, private "Finished / Let go" choice, left unset by default and never counted or shown to friends. This follows the Backloggd pattern found in web research.
3. **What happens to playthroughs.** Assumption: they disappear from the main flow. Marking a Done game as Playing again is a replay. Past runs and their notes stay viewable, read-only, in a collapsed "History" on the game page, and nothing is deleted.
4. **Up Next size and reordering.** Assumption: at most 5 games (StoryGraph's precedent). Reorder with move up / move down, or by dragging on desktop. The dashboard shows the top 3.
5. **Up Next on already-played games (today's "Replay" queue).** Assumption: Up Next is allowed on Want and Done games. A Done game in Up Next reads "Replay".
6. **The one default for adding.** Assumption: every add path adds as Want. The confirmation offers a one-tap "Put in Up Next" and an undo.
7. **Moving existing data.** Assumption:
   - Wishlist → Want, not owned;
   - Shelf → Want, owned;
   - Up Next → Want (or Done if played before), in Up Next, ordered by last edit, capped at 5;
   - Playing → Playing;
   - Played → Done, sub-type "Let go" if its only runs were abandoned, otherwise unset.
   Users get a one-time notice explaining the new statuses.
8. **One rating.** Assumption: one rating per game. Existing per-run ratings collapse into the game rating (the game rating if set, otherwise the best run rating). It is offered at Done.
9. **Where the prompts appear.** Assumption: "Why do I want this?" appears as an optional one-line field in the add confirmation. "What stayed with me?" appears as an optional field when marking Done. Both can be skipped and answered later from the game page, and an answer becomes a regular journal note.
10. **Old journal labels.** Assumption: every entry shows as a plain note with no Quick/Reflection label. Notes stay private, and moods, tags and titles are not shown.
11. **Steam import and friends' activity.** Assumption: in this spec they only switch to the new three labels. Smarter import suggestions belong to roadmap item #7.
