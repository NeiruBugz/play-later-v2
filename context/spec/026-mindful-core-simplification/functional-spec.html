Mindful Core Simplification

Topic: Replace the five-status model and playthrough bookkeeping with three statuses (Want / Playing / Done) plus an ordered Up Next queue; simplify the journal to plain notes with optional prompts; make adding a game and changing its status instant.  ·  Author: Nail Badiullin
Draft Verification: 0 of 90 criteria verified

At a glance

  • Every game has one of three statuses: Want (not started, owned or not), Playing, or Done (finished or let go).
  • Up Next is a short, ordered queue of up to 5 Want or Done games; a Done game in the queue reads 'Replay'.
  • A status only changes when the user changes it — one tap for the natural next step, two taps for any status, always undoable.
  • Adding a game is the same everywhere: one tap adds it as Want, with 'Put in Up Next', Undo and an optional 'why' prompt.
  • Journal entries become plain private notes; playthroughs are replaced by a read-only History, and existing libraries convert automatically.

Findings that shaped this spec

What the research phase discovered and where it landed. The technical detail behind each finding lives in research-notes.md.

  • A status set from the library is silently overwritten when a playthrough changes→ Status changes only when the user changes it
  • Up Next has no order; editing any game reshuffles it→ Ordered queue with manual reordering
  • Add paths disagree: some add as Shelf, the command palette as Up Next; the add dialog stays open silently→ One add behaviour, always Want
  • Ownership exists only as Wishlist vs Shelf→ Separate owned / not-owned marker
  • Logging time alone fails for games without a playthrough→ Time-only notes work for every game
  • Two ratings: game-level and per-playthrough 'Best rating'→ One rating per game
  • Older dropped games were recorded as finished when playthroughs were introduced→ Converted Played games get 'Let go' only when every playthrough was abandoned
  • Backloggd keeps one Played state plus an optional sub-type (Completed / Shelved / Abandoned / nothing specific)→ Done with optional private Finished / Let go
  • StoryGraph's Up Next is the only ordered queue found: max 5, drag to reorder→ Queue cap of 5 with reordering
  • Reflection prompts in StoryGraph, Day One and Letterboxd are optional and answerable later→ Skippable prompts, answerable from the game page
  • Goodreads mapped old 'dnf/abandoned' shelves into the new DNF shelf by meaning, keeping history→ Meaning-based conversion of existing libraries

Requirements

Terms used below

Library — the user's list of games, with a status filter at the top (All, Up Next, Want, Playing, Done).

Library card — one game in the library, shown either as a cover tile (grid view) or as a row (list view). Every card shows the game's status label and a "⋯" menu.

Game page — the page of one game. On phones it has a sticky bottom bar with the game's status.

Status control — the status label on a library card, the status pill on the game page, or the status pill in the phone bottom bar. Tapping it opens the status picker.

Play — one period of playing a game. A play starts when the game becomes Playing. It ends when the game leaves Playing, either to Done or back to Want. A game has been played before when it has at least one ended play.

Note — a piece of free text about a game, optionally with time played.

Log sheet — opens from the center "Log" button in the phone navigation or the "Log a session" button in the desktop sidebar. You pick a game, enter time played, and optionally write a note.

Journal — the "Journal" section in the navigation, listing all of the user's notes, newest first. Opening one note shows its note view.

Phone / desktop — screens narrower / wider than 768 pixels.

2.1. Three statusesInterview Codebase

Only Want, Playing and Done exist anywhere in the app.

Every game in a person's library has exactly one of three statuses: Want, Playing, or Done. No other status exists anywhere in the app.

Acceptance criteria — 3 (0 verified)
  • Pickers offer threeWhen the user opens any status picker in the app (library card, game page, phone bottom bar, Steam import), then they see exactly three options: Want, Playing, Done.
  • Filter choicesWhen the user views the library status filter, then the choices are All, Up Next, Want, Playing, Done, and no Wishlist, Shelf, or Played choice appears.
  • No other labelsWhen the user views any card, game page, dashboard, or profile, then the only status labels shown are Want, Playing, and Done, plus the queue markers "Up Next" and "Replay" (2.4).

2.2. A status only changes when the user changes itInterview Codebase

Nothing but the user changes a status; logging offers 'Mark as Playing'.

The status shown is always the last one the user chose. Logging time, writing notes, and editing details never change it on their own. When the user logs time for a game that isn't Playing, the confirmation offers a one-tap "Mark as Playing", and the user decides.

Acceptance criteria — 5 (0 verified)
  • Log keeps PlayingGiven a game is Playing, when the user logs time for it in the Log sheet, then the status still reads Playing.
  • Log on Want offers PlayingGiven a game is Want, when the user logs time for it in the Log sheet, then the status still reads Want and the confirmation "Logged {time} for {Game}" shows a "Mark as Playing" button.
  • Mark as PlayingGiven that confirmation is showing, when the user taps "Mark as Playing", then the game shows Playing and leaves Up Next if it was queued; when the user ignores it, then the game stays Want.
  • Card and page agreeGiven a game is Done, when the user edits its rating or writes a note, then the status still reads Done.
  • When the user sets a status on a library card, then the game page shows the same status in the page header and in the phone bottom bar.

2.3. One-tap status change, with undoInterview Codebase

One tap to the next status, two taps to any, undo for 5 seconds.

The user can move a game to its natural next status with one tap. The next-step button appears on library cards in both grid and list views, and on the game page:

Current statusOne-tap button
WantStart playing
PlayingMark done
DonePlay again

Any status can be reached in two taps: tap the status control, then tap a status in the picker. Every status change shows a confirmation with Undo for 5 seconds. Marking a game Done is the exception — it follows 2.7.

Acceptance criteria — 7 (0 verified)
  • Start playingGiven a game is Want, when the user taps "Start playing" on its library card, then the card shows Playing and a confirmation "{Game} is now Playing" with "Undo" appears for 5 seconds.
  • Play againGiven a game is Done, when the user taps "Play again", then the game shows Playing.
  • Picker opens directlyWhen the user taps the status control on a grid tile, a list row, the game page, or the phone bottom bar, then the status picker opens directly, without scrolling the page or opening a menu first.
  • No extra confirmationWhen the user taps a status in the picker, then the new status is shown immediately, without any further confirmation step.
  • Undo restoresWhen the user taps "Undo" within 5 seconds of a status change, then the game returns to its previous status and its previous Up Next place.
  • Undo removes new playGiven the user undoes "Start playing" or "Play again", when they expand History on the game page, then no new play has been added.
  • Undo with full queueGiven the game's previous Up Next place was taken by another game within those 5 seconds and the queue is now full, when the user taps "Undo", then the game returns to its previous status outside the queue and the user sees: "Up Next is full, so {Game} wasn't put back in the queue."

2.4. Up Next queueInterview Web Codebase

An ordered Up Next queue of up to 5 Want or Done games.

Up Next is an ordered list of up to 5 games the user intends to play next. It marks a game on top of its status; it is not a status itself.

Want and Done games can be in Up Next. A Done game in Up Next is labelled Replay; a Want game is labelled Up Next.

Changing a queued game between Want and Done keeps its place and switches its label.

A game that becomes Playing leaves the queue.

"Put in Up Next" and "Remove from Up Next" are in the "⋯" menu of every library card and on the game page. They are hidden for Playing games.

On the library with the Up Next filter selected, each queued game shows its place number and "Move up" / "Move down" buttons. "Move up" is hidden on the first game and "Move down" on the last. On desktop, games can also be dragged into a new order.

Acceptance criteria — 13 (0 verified)
  • Put in Up NextGiven a game is Want or Done and the queue holds fewer than 5 games, when the user taps "Put in Up Next", then the game appears at the bottom of the queue.
  • Queue fullGiven the queue already holds 5 games, when the user taps "Put in Up Next" on another game, then the game is not added and the user sees: "Up Next holds 5 games. Remove one to add this."
  • Hidden for PlayingGiven a game is Playing, when the user opens its "⋯" menu or its game page, then no "Put in Up Next" action is shown.
  • Numbered orderWhen the user selects the Up Next filter in the library, then the queued games are listed in the user's chosen order, numbered from 1 up to the number of queued games.
  • Move up/downWhen the user taps "Move up" or "Move down" on a queued game, then it swaps places with its neighbour, and the new order is still shown after reloading the page.
  • No move at edgesWhen the user views the first game in the queue, then it has no "Move up" button; when they view the last game, then it has no "Move down" button.
  • Drag on desktopGiven the user is on desktop, when they drag a queued game to a new position, then the queue shows the new order and keeps it after reloading the page.
  • Edits keep orderWhen the user edits any other detail of a queued game (rating, note, ownership), then the queue order does not change.
  • Remove from queueWhen the user taps "Remove from Up Next", then the game leaves the queue with its status unchanged, and the games below it each move up one place.
  • Starting leaves queueGiven a game is in Up Next, when the user starts playing it, then it shows Playing and is no longer in the queue.
  • Up Next to ReplayGiven a Want game is in Up Next, when the user changes it to Done, then it keeps its place and its label changes from "Up Next" to "Replay".
  • Dashboard top 3When the user views the dashboard, then the first 3 queued games appear in queue order with a "See all" link, and tapping the link opens the library with the Up Next filter selected.
  • Empty dashboardGiven the queue is empty, when the user views the dashboard, then they see: "Nothing queued yet — put up to 5 games in Up Next."

2.5. Owned or notInterview Codebase

An owned / not-owned marker replaces Wishlist vs Shelf.

Every game carries an "I own it / I don't own it yet" marker. It replaces the old difference between Wishlist and Shelf. The marker stays the same when the status changes. The "Not owned" tag is shown only on Want games, where it matters for deciding what to play or buy. The user changes it from the card's "⋯" menu or the game page.

Acceptance criteria — 5 (0 verified)
  • Owned by defaultWhen the user adds a game, then it is marked as owned.
  • Not owned tagWhen the user chooses "I don't own it yet" on a Want game, then the game shows a "Not owned" tag on its card and game page.
  • Marker survives statusGiven a Want game is marked as not owned, when the user changes it to Playing and later back to Want, then it still shows the "Not owned" tag.
  • Not owned only toggleGiven the Want filter is selected in the library, when the user turns on the "Not owned only" toggle that appears next to the filter, then only Want games marked as not owned are listed.
  • Private to friendsWhen a friend views the user's profile or activity, then no ownership information is shown.

2.6. Instant addInterview Codebase Web

Four add paths, one behaviour: add as Want, confirm, undo, keep searching.

There are four ways to add a game:

the search page;

the add dialog, opened by the "Add game" button on the dashboard and in the library;

the command palette (⌘K / Ctrl+K);

the "Add to library" button on the page of a game the user doesn't have yet.

All four behave the same:

One tap adds the game as Want.

A confirmation then shows "Added {Game} to Want", with "Put in Up Next", "Undo", and the optional "why" field of 2.8.

The confirmation stays for 8 seconds. It stays longer while the user is typing in the "why" field.

Search results appear as the user types.

The search stays open after adding, so several games can be added in a row.

Steam import is a separate, reviewed flow (2.13) and is not covered here.

Acceptance criteria — 9 (0 verified)
  • Add from searchWhen the user taps "+" next to a search result on the search page, in the add dialog, or in the command palette, then the game is added as Want and the confirmation "Added {Game} to Want" appears with "Put in Up Next" and "Undo".
  • Add from game pageWhen the user taps "Add to library" on the page of a game they don't have, then the game is added as Want, the same confirmation appears, and the page shows the game's status control.
  • Queue from confirmationWhen the user taps "Put in Up Next" in the confirmation, then the game joins the queue under the rules of 2.4.
  • Undo addWhen the user taps "Undo" while the confirmation is visible, then the game is no longer in their library, its queue place is freed, and any "why" answer given in that confirmation is gone.
  • Confirmation timeoutGiven the user has not touched the confirmation, when 8 seconds pass, then the confirmation disappears and the game stays in the library.
  • Live searchWhen the user types a game name in the add dialog, the search page, or the command palette and stops typing, then results appear within 1 second without pressing Enter.
  • Stays openGiven the add dialog or the command palette is open, when the user adds a game, then it stays open, the added result shows "In library", and the user can add another game.
  • Already in libraryGiven a game is already in the library, when it appears in search results, then it shows its status (and "Up Next #n" or "Replay" if queued) instead of "+", and tapping it opens the game page.
  • Add failsGiven the add cannot be saved, when the user taps "+", then the game is not added and the user sees: "Couldn't add {Game}. Try again."

2.7. Done follow-upInterview Web

Done applies at once; an optional private follow-up asks how it ended, rating, and what stayed.

Marking a game Done applies immediately and opens a small follow-up with three optional fields:

how it ended — Finished or Let go, neither selected by default;

a rating, pre-filled with the game's current rating if it has one;

"What stayed with you?".

The follow-up has "Save", "Skip", and "Undo". Closing it (the × button, tapping outside it, or the Escape key) counts as "Skip". After Save or Skip, the status stays Done. Changing it again uses the normal status control.

"How it ended" is private. It is never counted, totalled, or shown to anyone else. The user can change it later from the game page.

Acceptance criteria — 10 (0 verified)
  • Follow-up fieldsWhen the user marks a game Done, then the follow-up appears with "Finished" / "Let go" (neither selected), a rating, a "What stayed with you?" field, and "Save", "Skip" and "Undo" buttons.
  • Rating pre-filledGiven the game already has a rating, when the follow-up opens, then that rating is pre-filled; when the user changes it and taps "Save", then the new rating replaces the old one everywhere.
  • Skip and closeWhen the user taps "Skip", the ×, outside the follow-up, or presses Escape, then the game stays Done and nothing else is recorded.
  • Undo DoneWhen the user taps "Undo" in the follow-up, then the game returns to its previous status and nothing entered in the follow-up is kept.
  • What stayed noteWhen the user writes "What stayed with you?" and taps "Save", then the text appears as a note on the game page under the heading "What stayed with you?".
  • How it ended shownWhen the user picks "Finished" or "Let go" and saves, then the user's own game page shows "Done · Finished" or "Done · Let go".
  • Change how it endedGiven a game shows "Done · Let go", when the user changes how it ended to "Finished" on the game page, then the page shows "Done · Finished".
  • Hidden from friendsWhen a friend views the user's profile or activity, then they see "Done" without "Finished" or "Let go".
  • No countsWhen the user views their own profile, library, or dashboard, then no count or total of finished or let-go games appears anywhere.
  • Save failsGiven the follow-up cannot be saved, when the user taps "Save", then the follow-up stays open with what they entered and they see: "Couldn't save. Try again."

2.8. Optional promptsInterview Web

Two optional prompts at add and Done, answerable later or dismissed.

Two one-line prompts invite reflection at the key moments. Both can be ignored, dismissed, or answered later.

"Why do you want to play this?" — in the add confirmation, and on the game page of a Want game until it is answered or dismissed.

"What stayed with you?" — in the Done follow-up, and on the game page of a Done game until it is answered or dismissed for that Done.

Each prompt has a "Save" button; pressing Enter also saves. Dismissing a prompt (the × button) hides it for that game. An answer becomes a note headed by its question. Playing games show no prompt.

Acceptance criteria — 7 (0 verified)
  • Why field on addWhen the user adds a game, then the confirmation shows an optional "Why do you want to play this?" field with a "Save" button.
  • Ignore leaves no noteWhen the user ignores the field and the confirmation disappears, then the game is in the library with no note.
  • Answer becomes noteWhen the user types an answer and presses Enter or taps "Save", then the answer appears as a note on the game page under the heading "Why do you want to play this?".
  • Why on Want pageGiven a Want game has no "why" answer and the prompt was not dismissed, when the user opens its game page, then they see the "Why do you want to play this?" field and can answer it there.
  • What stayed on Done pageGiven a Done game has no "What stayed with you?" answer since it last became Done and the prompt was not dismissed, when the user opens its game page, then they see that field and can answer it there.
  • Dismiss promptWhen the user taps × on a prompt on the game page, then the prompt disappears and does not return for that game.
  • No prompt while PlayingWhen the user opens the game page of a Playing game, then no prompt is shown.

2.9. Plain notesInterview Codebase

Journal entries are plain private notes with optional time.

All journal entries are plain notes. A note has text and, optionally, time played, entered in hours in half-hour steps. It has no type label, mood, tags, or title, and it is not tied to a playthrough. Logging a session means writing a note with time played in the Log sheet. Notes are private.

Acceptance criteria — 5 (0 verified)

  • Simple composeWhen the user writes a note from the Log sheet, the "New note" button on a game page, or the Journal, then they see only a text field and an optional time field, with no type, mood, title, or playthrough choice.

2.10. Play history instead of playthroughsInterview Codebase

Playthroughs give way to an automatic, read-only play History.

Playthroughs disappear from the main flow. The game page has no Playthroughs panel, timeline, or "add playthrough" form. A collapsed, read-only History section lists the game's ended plays, newest first, each with its start date and end date. The play in progress is not listed. Notes stay in the game's notes list, each with its date. Nothing the user recorded before is lost.

Play dates are recorded automatically: a play starts on the day the game becomes Playing and ends on the day it leaves Playing. The game's details no longer have separate "started" and "completed" date fields.

  • No add playthroughWhen the user opens a library card's "⋯" menu, then no "Add playthrough" action is shown.

  • No History when unplayedGiven a game has no ended plays, when the user opens its game page, then no History section is shown.

2.12. Existing libraries move to the new modelInterview Codebase Web

Existing libraries convert at release by meaning; nothing is deleted.

When this change is released, every existing library is converted at once. Nothing is deleted.

ShelfWant, owned
Up Next, never played beforeWant, owned, in Up Next

Up Next. Existing Up Next games enter the queue with the most recently edited first. Only the first 5 are queued; the rest keep their new status outside the queue.

Ratings. Each game keeps its game rating. A game without one takes the highest rating from its earlier playthroughs.

Playthroughs. Earlier finished or abandoned playthroughs appear as ended plays in History (2.10). An in-progress playthrough becomes the current play of a Playing game.

Notes. Earlier notes appear as plain notes (2.9).

Explanation. Existing users see a one-time message explaining Want, Playing, Done and Up Next. Users who sign up after the change do not see it.

3. Scope and Boundaries

In-Scope

  • The three-status model (Want / Playing / Done) everywhere a status appears.
  • Statuses change only when the user chooses; nothing changes them automatically.
  • One-tap next-step buttons and undoable status changes on library cards (grid and list), the game page, and the phone bottom bar.
  • The ordered Up Next queue (at most 5 games), with reordering, the "Replay" marker, and the top 3 on the dashboard.
  • The owned / not-owned marker and the "Not owned only" toggle.
  • One add behaviour across the four add paths: add as Want, live search, a confirmation with "Put in Up Next" and Undo, and the search staying open. Plus "Add game" buttons on the dashboard and the library.
  • The Done follow-up (private Finished / Let go, rating, "What stayed with you?") and the "Why do you want to play this?" prompt.
  • Plain notes, with time-only logs working for every game.
  • A read-only play History replacing playthrough panels, timelines, and forms.
  • One rating per game.
  • Converting existing libraries, with a one-time explanation.
  • New labels in Steam import, friends' activity, search results, and the profile.

Out-of-Scope

  • The "What's Next" home screen beyond the dashboard's top 3 (roadmap Phase 3 #4).
  • A soft limit on how many games can be Playing (roadmap #5).
  • Reframing Times to Beat and removing "Your Pace" comparisons (roadmap #6).
  • Smarter Steam import suggestions beyond the label change and the 7-day rule (roadmap #7).
  • Suggestions of what to play next (roadmap #8).
  • Wishlist "already waiting" context before buying (roadmap #9).
  • Editing or deleting plays in History.
  • Sharing notes publicly or with friends; moods, tags, or note titles.
  • Ownership from subscriptions and consoles (roadmap Phase 4).
  • A welcome tour for new users (spec 013, parked).
