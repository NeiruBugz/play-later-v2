# Feature Brief: Release days

- **Understanding:** Confirmed 2026-11-12
- **Sources:** consulted — codebase research, web research, owner decisions from this session (2026-11-12); not consulted — internal knowledge sources (none configured; owner declined discovery on 2026-11-10)
- **Generated by:** /awos:spec on 2026-11-12

## 1. Vocabulary

- **Game** — one title from the public game catalogue (IGDB), with its name, cover and release date. The same game is shared by everyone who adds it. [code]
- **Library** — the games a person has added to SavePoint. Each game in it has a status and an ownership marker. [code]
- **Status** — where a game stands for the person: **Want**, **Playing** or **Done**. [code]
- **Owned / Not owned** — a marker on a library game. Every newly added game counts as owned until the person picks "I don't own it yet"; it then shows a "Not owned" tag. [code]
- **Wishlist** — not a screen or a word in the app. It means "Want games marked Not owned", reachable as the library filtered to Want + "Not owned only". The product documents still say "wishlist". [code]
- **Up Next** — a short ordered queue (at most 5) of games the person means to play next. [code]
- **Home** — the first screen after sign-in: the "Continue?" question, the Up Next shelf, "Also playing" and a counts line, in that fixed order. [code]
- **Release date** — the day a game first comes out. In the catalogue it can be known to the **day** (14 Mar 2027), the **month** (Mar 2027), the **quarter** (Q2 2027), the **year** (2027), or not at all (**TBA**, "to be announced"). [web]
- **Released / unreleased** — a game is unreleased while its release date is still in the future (or unknown); released once the day has come. [user]
- **Release day** — the calendar day a game comes out, in the person's own timezone. [web]
- **Exact (stable) date** — a release date known to the day. Only these appear in the release calendar and on Home; vaguer dates are shown only as labels on library cards and the game page. [user]
- **Release calendar** — a new page listing the person's library games with an exact release date later than today, in date order. [user]
- **Coming soon (Home)** — a new quiet section on Home listing library games coming out in the next few days, including today's releases; it is the way into the release calendar. [user]

## 2. What it does today

The feature does not exist yet. [code] Release dates sit next to it in a few places:

- When a game is first added to SavePoint by anyone, its release date is copied from the catalogue once and never updated again. [code]
- The game page shows the year at the top (read live from the catalogue) and a full date further down labelled **"Released"**, even when the date is in the future. [code]
- Search results, the add dialog and the quick search show only the year. [code]
- Library cards and Home show no release date at all. [code]
- Nothing in the app knows whether a game is released or not, and nothing lists upcoming games. [code]

## 3. What it depends on

- The game catalogue (IGDB) for release dates and how precise they are. The catalogue limits how many requests the app may send per second. [web]
- The person's library: which games they added, their status and the Not owned marker. [code]
- Opening Home or the library: there is no background job in SavePoint, so the app can only check for changed dates when the person opens it. [code][user]
- The person's device clock and timezone, to know what "today" is. SavePoint does not store a timezone for anyone. [code]

## 4. What it changes

- Library cards for unreleased games show the release date at its real precision. [user]
- Home gets a "Coming soon" section below "Also playing": today's releases ("Out today") and games coming out in the next few days. [user]
- A new release calendar page appears, reached from that Home section, and lists only games with an exact date. [user]
- Release dates stay current with the catalogue for games people are waiting on, so delays show up. [user]
- Everyone who has the same game sees the same corrected date, because the game record is shared. [code]
- All of this is visible only to the signed-in person for their own library; nothing is shared or sent anywhere. [user]

## 5. Quirks

1. **Normally:** a game's release date follows the catalogue. **Here:** it is copied once and frozen, so a delayed game keeps its old date. — This spec must fix it, or the release-day card fires on the wrong day. [code]
2. **Normally:** a vague date like "2027" stays vague. **Here:** only one exact-looking date is stored, and the catalogue fills vague dates with a placeholder day (such as 31 Dec). — Without the precision, "2027" would show as "31 Dec 2027" and trigger a release-day card that day. [code][web]
3. **Normally:** an unreleased game you add goes on your wishlist. **Here:** every added game counts as owned until you change it. — Most unreleased games in a library will be "owned" (a preorder, or just the default), not "wishlisted". [code]
4. **Normally:** you can't play a game before it's out. **Here:** an unreleased game can be Playing, Done or in Up Next, and Home may ask "Start {game}?" for it. — The calendar and card must decide what to do with unreleased games in any status. [code]
5. **Normally:** "today" means your local day. **Here:** SavePoint stores no timezone, and the server runs on a different clock. — "It's release day" has to be decided on the person's device. [code]
6. **Normally:** the game page says "Releases" for a future date. **Here:** it says "Released: 14 Mar 2027". — An adjacent mislabel this spec touches. [code]
7. **Normally:** a game's release date is the one for your platform. **Here:** it is the earliest release anywhere (any platform, any region, sometimes early access). — The "release day" may be someone else's release day. [web]
8. **Normally:** "no date" means TBA. **Here:** a missing date can mean TBA, missing catalogue data, or a failed lookup, and today these look the same. [code]
9. **Normally:** an app could add a new link to its bottom menu. **Here:** the phone bottom menu is full (5 slots), and the desktop sidebar has no spare section. — The calendar needs a way in that isn't a new menu slot. [code]
10. **Normally:** Home can show anything from the library. **Here:** spec 028 fixed Home's order and requires the first Up Next cover to be fully visible on a phone without scrolling. — A new card must not push it down. [code]

## 6. Open questions

1. ~~Which games count?~~ **Resolved [user]:** any library game whose release date is later than today, whatever its status or ownership. Supersedes the earlier "wishlisted" wording.
2. ~~Where does the calendar live?~~ **Resolved [user]:** Home shows releases close to today, and that section leads to the full calendar. *Still assumed:* "close to today" means today plus the next 14 days (Backloggd uses 7/14-day groups [web]); when nothing is coming in that window the section is hidden, so the calendar also gets a quiet link on the library page.
3. ~~Calendar shape.~~ **Resolved [user]:** the calendar works only with exact (day-precise) dates; a game joins it once its exact date is announced and moves when that date changes. Supersedes the earlier decision that month, quarter and year dates count and the "Sometime in …" rows. *Still assumed:* a date-ordered list grouped by month (Steam and Backloggd use lists, not month grids [web]); the calendar ends at the last exactly-dated game.
4. ~~Where on Home?~~ **Resolved [user]:** below "Also playing" (and so below the Up Next shelf). *Still assumed:* above the counts line, untinted.
5. ~~What happens when a date moves?~~ **Resolved [user]:** a quiet "Moved from 14 Mar" line on the library card and the calendar entry. *Still assumed:* shown for 14 days after the app notices the change, then it disappears; only for moves between exact dates (a vague date becoming exact is an announcement, not a move).

**Big picture [user]:** the pain is **no overview** of what's coming up across the library. If only one piece ships first, it is **Coming soon on Home**. Out of scope: notifications outside the app, per-platform or per-region dates, discovering games not in the library, and store links or prices.
6. ~~After the release day.~~ **Resolved [user]:** the game leaves Coming soon and the calendar the next day, and its library card stops showing a date.
7. ~~Game page label.~~ **Resolved [user]:** in scope — future dates read "Releases …", past dates keep "Released …".
8. ~~TBA vs unknown.~~ **Resolved [user]:** "Date TBA" only when the catalogue says TBA; nothing when the date is simply missing.
9. ~~Freshness.~~ **Resolved [user]:** a change shows up within a day for games coming out in the next two weeks, within a week otherwise.
