## Codebase findings

### Data model
- `Game.releaseDate DateTime?` — no precision, no fetched-at marker (`prisma/schema.prisma:91-114`, field at :97). Shared across users.
- `LibraryItem` unique `(userId, gameId)`; `status` WANT|PLAYING|DONE (default WANT), `isOwned` default **true**, `upNextPosition` 1..5, `platform` free string, `statusChangedAt` (`schema.prisma:116-147, 252-261`).
- No user timezone field on `User` (`schema.prisma:58-89`). `user.eveningMinutes` exists (:76).
- "Wishlist" = WANT + `isOwned=false`. Migration `20261104120000_mindful_core_model/migration.sql:49` set `isOwned=false WHERE status='WISHLIST'`; spec 026 §2.5 maps Wishlist → "Want, not owned" (`026 functional-spec.md:140-148, 286`). UI label is "Not owned" (`entities/library-item/ui/not-owned-tag/not-owned-tag.tsx:5-17`, shown only when WANT && !isOwned); filter "Not owned only" only with `status: WANT` (`entities/library-item/api/get-library.server.ts:31`; `features/filter-library/lib/use-library-filters-state.ts:94`). The word "wishlist" never appears in UI.
- Every add and import sets `isOwned: true` (`entities/library-item/api/add-game-to-library.server.ts:31-38`; 026 AC :143). Flip via `set-ownership.server.ts`. `isOwned=false` persists through PLAYING/DONE (026 :140,145).
- No status transition checks release date (`entities/library-item/api/set-library-item-status.server.ts`); unreleased Up Next game → Continue panel asks "Start {game}?" (`widgets/dashboard-page/model/use-continue-question.ts:31-34,62-69`).

### IGDB client
- `igdbFetch` POST, Bearer + Client-ID, 8 s abort, one retry (401 → refresh token; 429 → 300–600 ms wait) (`shared/api/igdb/fetch.ts:32-66,87-106`). No proactive limiter/concurrency cap. Stale comment in `search.ts:10`.
- In-memory LRU 10 min / 500 entries keyed by query text, per instance (`response-cache.ts:65-71`).
- Batching: `where game_id = (a,b,c); limit N` (`queries.ts:14-20`), used by `getTimesToBeatForGames` (`entities/game/api/get-times-to-beat.server.ts:73-87`). No batch `/games` by ids helper.
- Errors: `IgdbHttpError` (`errors.ts:21-50`) rewrapped as `UpstreamError` (`get-game-by-id.ts:47-64`). Enrichment logs warn and retries later (`ensure-game-enrichment.server.ts:72-83`); per-field staleness e.g. `timesToBeatFetchedAt` > 30 d (:13,49-54). `Game.updatedAt` unusable as refresh marker.
- Lazy enrichment callers: game page with 1.5 s cap (`entities/game/api/get-game-details.server.ts:25-37,105`), add (`features/add-game/api/add-game.worker.ts:25`), Steam import (`import-game-to-library.worker.ts:113`), backfill script. Home/library loaders call none.

### IGDB date formats (live, 2026-11-12)
Owner ran `inspect:igdb-release-dates` against live IGDB on 2026-11-12. Verbatim payloads for the mapper tests: `src/shared/api/igdb/__fixtures__/release-dates-live-2026-11-12.json` (the 8 `dateFormats` rows plus one game per case, keyed `day`, `month`, `year`, `q1`, `q2`, `q3`, `q4`, `tbd`, `mixedStatuses`, `exactEarlyVagueLater`, `noFirstReleaseDate`).

`/date_formats` (the 0-7 mapping is confirmed, equal to the legacy `category` enum):

| id | format | our precision |
|---|---|---|
| 0 | `YYYYMMDD` | DAY |
| 1 | `YYYYMM` | MONTH |
| 2 | `YYYY` | YEAR |
| 3 | `YYYYQ1` | QUARTER |
| 4 | `YYYYQ2` | QUARTER |
| 5 | `YYYYQ3` | QUARTER |
| 6 | `YYYYQ4` | QUARTER |
| 7 | `TBD` | TBA |

Placeholder-day rule observed in `release_dates[].date` (identical in `games.first_release_date` when that entry wins):
- DAY: the real day. Netherwake: `date` 2026-11-13, `human` "Nov 13, 2026".
- MONTH: first day of the month. Former Dawn (id 322514): `date` 2026-12-01, `human` "Dec 2026", `m` 12, `y` 2026.
- YEAR: last day of the year (Dec 31). 5 Star Fishy: `date` 2026-12-31, `human` "2026", `m` 12, `y` 2026.
- QUARTER: last day of the quarter, and `y`/`m` carry the quarter's last month. Phase Nexus Q1 2027: `date` 2027-03-31, `m` 3. Piggy One Super Spark Q2 2027: 2027-06-30, `m` 6. Hunter: The Reckoning - Deathwish Q3 2027: 2027-09-30, `m` 9. Polda 8 Q4 2026: 2026-12-31, `m` 12.
- TBD: no `date`, no `y`, no `m`; only `human` "TBD". Neon District (three TBD entries, no `status`).
- Duplicate entries occur (Former Dawn 322514 has two identical Dec 2026 rows; Polda 8 has two Q4 2026 and two Q4 2027 rows; Hunter has three identical Q3 2027 rows), so the mapper must tolerate repeats.
- `status` and `date` can be absent on an entry (Sligga Trigger YEAR entry has no `status`).

`games.first_release_date` behavior (it is not simply the minimum `date`):
- Azur (387953): entries Q3 2027 (`status` 6), Q2 2027 (`status` 2), Q1 2027 (`status` 1); `first_release_date` = Q3 2027 (2027-09-30). The full-release entry wins over the earlier alpha/beta entries.
- The Legend of Khiimori (318175): entries exact 2026-03-03 (`status` 3), Q1 2027, 2027 (both without `status`); `first_release_date` = 2026-03-03. The exact early entry wins over later vague entries.
- DDD: Dice, Dungeons, and Drakes (395123): its only entry is a dated Q3 2027 entry with `status` 2 (Beta-status by the owner's reading); `first_release_date` is absent. A game can have a dated entry yet no `first_release_date`.
- Neon District (124201) and Little Taichi: The Adventrure of Myth (342992): TBD entries only; `first_release_date` is absent.
- Consequence: a game whose precision comes from release entries must be matched to the entry whose `date` equals `first_release_date`; when `first_release_date` is absent there is no stored date.

Every sampled `date` (38 entries) is UTC midnight (`date % 86400 === 0`); IGDB carries no time of day.

`release_dates[].status` ids 1, 2, 3 and 6 were seen, but their names were not requested; the code must not depend on them.

## Web research findings

- [web] IGDB `release_dates` fields: `date`, `date_format` (ref `/v4/date_formats`, replaces deprecated `category`), `d`, `m`, `y`, `human`, `platform`, `release_region` (replaces `region`), `status` (ref `/v4/release_date_statuses`). Legacy `category` enum: 0 YYYYMMMMDD, 1 YYYYMMMM, 2 YYYY, 3–6 YYYYQ1–Q4, 7 TBD. `date_formats` id mapping not documented — query once; don't assume equals 0–7. — https://api-docs.igdb.com/
- [web] Release date statuses (contributor guide): Alpha, Beta, Early Access, Advanced Access, Full Release, Canceled, Offline, …; per platform; earliest date first; blank date = TBA. — https://github.com/twitchtv/igdb-contribution-guidelines/wiki/Release-Date
- [web] `games.first_release_date` = earliest release, no precision info. Vague dates stored as placeholder days; sources disagree (end of period vs Dec 31 for year / 1st for month). Never render as a day unless format is exact-day. — https://github.com/mperezfo/Gamelog/pull/178 , https://github.com/ChronosSF/myvideogamelist/issues/351
- [web] Rate limit 4 req/s, 8 concurrent, 429 on excess; multi-id `where id = (8,9,11);`; `limit` default 10, max 500; multiquery max 10 per request; webhooks per endpoint available. — https://api-docs.igdb.com/
- [web] Steam store date display: exact / month / quarter / year / "Coming Soon"; locked within 14 days of release. — https://partner.steamgames.com/doc/store/release_dates
- [web] Steam personal calendar: only exact-dated games; 8 weeks day-by-day; weekend releases shown Monday; delays near launch remove the game until release. — https://partner.steamgames.com/doc/marketing/visibility/personalcalendar
- [web] Backloggd "Coming soon": next 7 days / next 14 days / later, filterable to wishlist; vague dates as "2026 Q4", "TBD"; dates can regress to TBD. — https://backloggd.com/changelog/1_11_0 , https://backloggd.com/roadmap/ , https://backloggd.com/changelog/1_10_0
- [web] Common shape: agenda list grouped by time bucket, not month grid; calendars include only exact dates; vague as labels.
- [web] Launch timing: regional midnight vs global unlock; IGDB has no time of day → treat release day as calendar date in user's timezone; don't shift a UTC-midnight timestamp. — https://www.pcgamer.com/games/fps/borderlands-4-global-release-times-mean-some-of-you-can-play-a-day-earlier-than-expected
- [web] Delays: Gamelog only proposes exact future date changes and skips released games (freeze after release). — https://github.com/mperezfo/Gamelog/pull/178
- [web] Calm tech / dark patterns: avoid countdowns and "N days left". — https://spectrum.ieee.org/calm-tech , https://arxiv.org/pdf/1907.07032
- Open to verify against live IGDB: `human` strings per format; `date_formats` id mapping; placeholder day per format; whether TBD games have null `first_release_date`.
