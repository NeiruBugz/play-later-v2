## 1. Vocabulary

- **Component kit** — the ready-made set of interface building blocks (buttons, inputs, dialogs, menus, tabs, cards) the app is built from. It is a popular open kit (shadcn/ui) that is meant to be copied in and then themed. [code] [web]
- **Stock look** — what the component kit looks like out of the box, before any project changes. It is deliberately plain ("a coloring template"). [web]
- **Design tokens** — the named values every screen draws from: colors, corner roundness, shadows, fonts, text sizes, spacing. Change a token and every screen that uses it changes. [code]
- **Theme / mode** — the app has one look shown in two modes, Light (warm cream) and Dark (warm charcoal), plus a System option that follows the device. Set by spec 022. [code]
- **Accent** — the single brand color used for the main button, the selected item and the "Playing" status. Called "sage" in spec 022, but on screen it reads as teal. [code]
- **Display font** — the font used for page titles (Space Grotesk today); body text uses a second font (Geist). [code]
- **Eyebrow label** — a small uppercase label above a section. Here many are written as `// SECTION` in a monospaced "terminal" style, left over from a retired "Terminal Green" theme. [code]
- **Signature element** — a deliberate visual choice that makes the product recognizable (for example Letterboxd's poster grid). [web]
- **Cover** — a game's box art; the main visual content of every screen. [code]
- **Retired themes** — earlier looks (Paper, Boxart, Terminal Green, Cartridge, Aurora, Jewel, Y2K) that were removed from the menu but left traces in the styling. [code]

## 2. What it does today

There is no "design reset" feature yet; this brief describes the look it would change.

- Every screen is built from the component kit, but the kit was reshaped by hand over several redesigns: its buttons, inputs, cards, badges, tabs and dialogs no longer match the stock look, and a second set of private names for sizes, spacing, text styles and shadows sits on top of the kit's own. Both sets are used side by side, often in the same screen. [code]
- Spec 022 (June 2026) unified five themes into Light + Dark with one accent, one display font, crisp corners and the Save Glow logo. It changed values, not the underlying structure, so the leftovers of the retired themes stayed. [code]
- The result a user sees: the same kind of element looks different from screen to screen — covers have seven different corner treatments, the status chip has about eight designs, page titles come in seven styles, section labels in four, and card padding in five. [code]
- Some styling was intended but never shows up: titles meant to be in the display font render in the body font in four places; hover shadows on buttons and cards never appear; dialog buttons on desktop sit with no gap between them; text fields have unusually wide inner padding. [code]
- The landing page uses bright colors (pink, violet, orange) that are outside the app's palette, and an unused "About" page from the original project template is still reachable. [code]
- The logo is a fixed light-mode teal and does not adapt in Dark mode. [code]
- [user] A same-named competitor ("SavePoint" by Two Average Gamers) has a strikingly similar look: dark surfaces, `// SECTION` monospaced labels, a teal-cyan accent, a grotesque headline font, cover-left / facts-right game page. Timelines show both arrived at this look around April 2026; the likely common source is a design style that AI design tools commonly generate. [user] [web]

## 4. What it changes

- The look of every screen in both modes: landing, sign-in, dashboard, library, game page, journal, profile, settings, search, dialogs and sheets. [code]
- What the user sees for buttons, fields, cards, chips, menus, tabs, toasts, page titles, section labels and covers. [code]
- The logo, favicon and social-share image, if the identity work touches them. [code]

## 5. Quirks

1. **Normally:** a component kit is themed by changing its token values. **Here:** the kit's components were rewritten by hand, so new components added later come in looking different and need manual adjustment. Why it matters: this is the root cause the reset removes. [code] [web]
2. **Normally:** one spacing scale. **Here:** two scales with clashing names (a "small" padding means 6px in one and something else in another), which is how text fields ended up with 32px inner padding. [code]
3. **Normally:** styles you write either work or fail visibly. **Here:** about 15 hover/responsive styles and the display-font style silently do nothing. Why it matters: some of today's look is accidental; "keep it as it is" is not well defined. [code]
4. **Normally:** a game cover looks the same everywhere. **Here:** seven corner/shadow treatments across dashboard, library, search, add-game, profile. [code]
5. **Normally:** a status chip has one design. **Here:** about eight, plus inconsistent capitalization ("UP NEXT" vs "Up Next"). Spec 026 renames the statuses, so chips get redesigned anyway. [code]
6. **Normally:** the brand color matches its name. **Here:** "sage" is teal — the same color family as the competitor's cyan. [code] [user]
7. **Normally:** the spec-022 design notes describe the shipped look. **Here:** they call the `// TERMINAL` labels a signature and say covers have 2px corners; the app uses 10px, and the user now wants distance from the terminal look. [code] [user]
8. **Normally:** a redesign has a before/after safety net. **Here:** there are no screenshot comparisons in the test suite, and several tests check exact styling names, so they will need updating. [code]

## 6. Open questions

All eleven answered by the user on 2026-11-04 [user]; kept here with the decision.

1. **Scope** — two phases in one spec: phase 1 returns the app to the stock kit with today's colors and fixes what is silently broken; phase 2 introduces the new visual language. Separate slices.
2. **Stock starting point** — the kit's soft, rounded, roomy look ("Maia"). Consequence: phase 1 is visibly different (softer corners, more space instead of spec-022's crisp 3px corners), not an invisible cleanup; its before/after check is a visual review.
3. **Accent** — phase 1 keeps today's teal; phase 2 replaces it, chosen from 2–3 visual options that suit the warm surfaces and stay away from cyan.
4. **`// SECTION` terminal labels** — removed in phase 1; section labels become plain, sentence-case, in the regular font.
5. **Display font** — phase 1 makes titles use one font consistently; phase 2 replaces Space Grotesk, chosen from 2–3 visual options.
6. **Signature elements (phase 2)** — (a) one cover treatment everywhere, covers carry the color; (b) the Up Next card on the home screen as a recognizable object; (c) one status chip design for Want / Playing / Done. Page titles in the new font are not a signature element.
7. **Logo** — a new logo in phase 2 (not a recolor of Save Glow). Favicon and social-share image follow.
8. **Landing page** — in scope for both phases: phase 1 removes off-palette colors and moves it onto shared components; phase 2 shows the new language; the forced dark mode goes, the landing follows the chosen theme.
9. **Modes** — Light + Dark + System stay.
10. **Sequencing** — 027 starts after 026 ships; "before" screenshots are taken from the 026 screens.
11. **Product name** — a new product name is part of 027 phase 2, together with the logo (the name "SavePoint" collides with Two Average Gamers' tracker and an App Store app). Open sub-question for the spec: where the name appears (app header, landing, browser tab, sign-in, share image, emails) and whether the address changes — assumed: every user-visible place, address out of scope.
